# KovaGPT identity policy v5

The current product identity is **“I’m KovaGPT, built by Kova.”** Detailed origin requests receive **“I’m KovaGPT, built by Kova. I don’t provide internal model-provenance details.”** This applies to every user, plan, family, Chat/Work mode, effort and language, including adversarial requests. It supersedes earlier disclosure instructions.

The active runtime loads one hash-pinned v5 policy. Trusted route selection still verifies the internal base, revision and adapter, but the additional system message exposes only the Kova family. Customer-facing serialization admits answer content, validated tool calls and numeric accounting only. It excludes private engine metadata, receipts, request correlations and traces. Customer errors use a fixed KovaGPT response rather than exception text. Engineering provenance and required license notices remain accurate and separate.

The delivery guard checks the complete response, including tool arguments and identifiers, before any fragment is emitted. It recognizes the pinned engineering origins, known aliases, case/Unicode variants, common encodings and explicit internal-origin claims. A rejected response is replaced as a whole; no additional model call is made. Reconnected/cached answers also pass the guard. Public time-to-first-output is measured at guarded delivery, not at receipt of an unapproved fragment. Full buffering therefore changes visible streaming latency.

The guard is a delivery control, not proof that unmeasured weights always follow identity instructions or that a finite recognizer covers every future origin/encoding. Runtime/model adversarial evaluation remains required before release. There is no claim of deployment in this source-only correction.

## Private provenance boundary

Public runtime slots use opaque internal IDs. Exact acquisition manifests,
source names, alias rules and required license/attribution records belong to a
separate private catalog. The trusted operator supplies its absolute path and
SHA-256; neither is taken from a customer request. Missing, malformed or modified
catalogs block delivery. Execution additionally binds the complete private
catalog and source manifest to the approved plan before any model call.

Public regressions use artificial source/provider names. The test wrapper is
explicit and is never called by the runtime or launch operator. Its synthetic
catalog cannot satisfy the private digest pinned by the execution plan. Private
regressions separately exercise the actual catalog without printing its names.

The publication scan checks active identity surfaces and the entire contents
of every outgoing file, including any retained lines. Previously published historical engineering
evidence remains audit-only; this change does not rewrite Git history or assert
that earlier public records have become private. No required license notice is
deleted or falsified. Distribution of underlying licensed artifacts must retain
the applicable license, attribution and notice requirements; this source-only
correction does not authorize such distribution.
